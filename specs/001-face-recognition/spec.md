# Feature Specification: 本地人脸识别认证

**Feature Branch**: `001-face-recognition`

**Created**: 2026-08-18

**Status**: Delivered(2026-08-21 实现完成,待全量验证)

**Input**: 为 kiran-authentication-service 增加本地人脸识别认证(非 ks-authhub 远端比对方案):
本地完成人脸检测/特征提取/比对,算法参考 ncnn_test.cpp(YuNet+SFace);
录入在 kiran-control-panel 中进行(面板实时预览、拍照传图),特征由认证服务持久化并管理。

## 范围与术语

- 本需求跨两个仓库:**kiran-control-panel**(录入 UI 与交互,本文档主责)与
  **kiran-authentication-service**(本地识别设备/驱动/daemon 配套)。
- "软人脸(SOFT_FACE)"专指人脸比对在远端服务器执行的 ks-authhub 方案,与本需求无关,
  命名上严格区分;本需求对应 `KAD_AUTH_TYPE_FACE` / `DEVICE_TYPE_FACE`。
- 用户 = 操作系统账户;每个账户的特征由账户所有者在控制面板中管理。

## User Scenarios

### US1 控制面板人脸录入 (P1)

用户在人脸页点击录入并通过密码验证后进入录入页;录入页立即打开摄像头实时预览,
用户对准摄像头点击"拍照/录入",面板将当前帧提交给认证服务处理并展示进度;
成功后特征出现在列表,失败保留预览可重试;取消/超时/关页均正确清理。

**验收场景**:
1. 点击录入并通过密码验证 → 切入录入页,预览区立即显示黑底,首帧到达后显示摄像头画面(无上一页 UI 残留)
2. 预览中点击"拍照/录入" → 当前帧随录入请求提交,进度反馈
3. 成功 → 进度 100%,特征出现在列表并可参与认证
4. 失败(未检测到人脸/图像无效/重复) → 提示具体原因,保留预览可直接重试
5. 取消/关闭页面 → 流程终止、关闭摄像头、不保存特征
6. 预览停留 2 分钟无操作 → 自动关闭摄像头并返回特征管理页
7. 缩放窗口 → 预览随窗口缩放(最小 272×272),画面等比不变形

### US2 登录/锁屏人脸识别认证 (P1)

登录/锁屏等认证场景选择人脸认证:服务端自行控制摄像头本地识别,本人通过、
他人拒绝;失败原因(摄像头不可用/不匹配/超时)以明确文案展示;可随时切换密码。

**验收场景**:
1. 本人 → 认证通过
2. 他人 → 拒绝并提示"人脸不匹配"
3. 摄像头不可用 → 提示"无法打开摄像头"(而非笼统的"特征不匹配")
4. 识别窗口(10 秒)内无人 → "识别超时"
5. 识别中切换密码/停止 → 结果丢弃、切换流畅
6. 可切换锁屏(无目标用户)→ 全库比对,命中后由 daemon 反查用户并校验

### US3 人脸特征管理 (P2)

查看已录入特征列表;重命名、删除即时生效,服务重启后保持;删除后不再参与认证。

## Functional Requirements

- **FR-001**: 人脸检测、特征提取与比对全部在本机完成,不依赖网络或远端服务
- **FR-002**: 录入页切入后立即开启摄像头实时预览;处理完成、失败、取消或关页时关闭摄像头
- **FR-003**: 点击"拍照/录入"捕获当前帧,缩放至 640×480 以内并按 JPEG 质量 85 压缩后
  base64 放入录入请求附加信息 JSON 提交(单条 D-Bus 消息上限 128MB,压缩后无超限风险);
  录入会话在拍照时建立(预览阶段不占用认证服务设备)
- **FR-004**: 录入过程持续上报进度与结果;成功返回特征 ID,失败提示具体原因且保留预览可重试
- **FR-005**: 录入特征持久化保存,服务重启后仍可查询和参与认证
- **FR-006**: 提供特征查询/重命名/删除能力,操作即时生效并持久化
- **FR-007**: 识别接口返回匹配、不匹配或失败及可理解的原因
- **FR-008**: 设备忙(录入/识别进行中)时新请求明确拒绝并提示
- **FR-009**: 识别停止请求发出后进行中的结果必须丢弃
- **FR-010**: 未检测到人脸/质量不足/摄像头不可用/超时等失败场景给出明确可理解的提示;
  daemon 对非软认证类型转发设备上报的具体失败原因
- **FR-011**: 识别相似度阈值可配置(kad.ini [Face] Threshold,默认 0.6),默认值保证他人误通过率达标
- **FR-012**: 录入与认证画面出现多张人脸时,均取面积最大的一张处理
- **FR-013**: 识别在超时窗口(默认 10 秒)内持续采集比对,单帧不匹配不结束;
  窗口结束区分结果:比对过且均不匹配 → "人脸不匹配";未检测到可比对人脸 → "识别超时"
- **FR-014**: 可切换锁屏场景(daemon 不指定目标用户)下与本地全库特征比对并返回命中特征 ID,
  由 daemon 既有链路反查用户并校验合法性
- **FR-015**: 重复录入拒绝并提示"该特征已录入"(录入特征与库中已有特征做余弦相似度比对,
  超过识别阈值即判定为同一人脸并拒绝)
- **FR-016**: 每个操作系统账户最多录入 10 个人脸特征,超限拒绝并明确提示
- **FR-017**: 录入页预览停留超过 2 分钟无操作时自动取消(处理中先停止)并返回特征管理页
- **FR-018**: 预览区首帧到达前用不透明黑遮罩覆盖(QVideoProbe 探测首帧后摘除),
  不得透出上一页残留 UI
- **FR-019**: 预览限定 640×480@30fps、RGB32 像素格式以降低 CPU 占用;
  预览随窗口缩放(最小 272×272)
- **FR-020**: 人脸驱动可经控制面板驱动管理禁用/启用:禁用后设备下线、人脸认证不可用,
  启用后恢复;开关状态持久化
- **FR-021**: 范围排除:不包含活体检测(照片/屏幕可通过,交付文档说明边界);
  不包含人走监测(检测不到人脸自动锁屏),设备仅支持"一次识别返回一个结果"

## Success Criteria

- **SC-001**: 识别认证不阻塞 PAM 链路:识别中可随时切换/停止,切换响应与现有体验一致
- **SC-002**: 本人识别通过率不低于 95%(本人连续 20 次尝试,通过不少于 19 次)
- **SC-003**: 他人误通过率不高于 0.1%(非本人尝试 1000 次,误通过不超过 1 次)
- **SC-004**: 首次录入成功率不低于 90%(正常使用条件下 20 次录入,成功不少于 18 次)
- **SC-005**: 特征增删改查操作完成后即时生效,无需重启服务
- **SC-006**: 断开网络后录入、管理与识别全流程仍可正常工作

## 交付说明

- 算法模型(yunet/sface,ncnn 格式,OpenCV Zoo 衍生,许可见 kiran-authentication-devices-sdk 仓库 NOTICE)不在本仓库
  与认证服务仓库分发,由 kiran-authentication-devices-sdk 仓库提供,安装至
  `/usr/share/kiran-authentication-service/models/face/`;开发调试可用
  `KAS_FACE_MODEL_DIR` 指向本地模型目录。

## Known Limitations

- 无活体检测:照片/屏幕画面可能通过认证
- 仅默认 V4L2 摄像头,无硬件人脸设备(双目/红外)
- 面板预览在大窗口快速运动时可能出现画面撕裂(Qt5 V4L2 后端限制,暂接受)
- 重复录入判定基于与库中特征的余弦相似度(阈值同识别阈值),相似人脸会被判重
